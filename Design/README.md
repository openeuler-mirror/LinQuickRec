# 设计文档目录

本目录包含 LingQuickRec 搜推广时延模拟系统的核心子系统设计方案。

## 文档列表

### 1. [错误码体系设计方案](./error_code_design.md)
- **概述**：统一微服务架构的错误处理机制
- **核心特性**：结构化错误码、强类型安全、跨服务传播
- **适用场景**：服务间错误传递、客户端错误处理、监控告警

### 2. [日志系统设计方案](./logger_system_design.md)
- **概述**：统一日志记录和可观测性基础设施
- **核心特性**：多级别日志、多输出目标、文件轮转、trace_id支持
- **适用场景**：开发调试、生产监控、问题诊断、性能分析

## 设计原则

### 统一性原则
- 所有服务采用相同的错误处理和日志记录标准
- 保持与现有代码的向后兼容性

### 可观测性原则
- 支持全链路追踪（trace_id传递）
- 结构化输出便于监控系统采集
- 丰富的上下文信息便于问题定位

### 性能友好原则
- 异步日志避免阻塞主流程
- 级别过滤减少不必要的日志输出
- 高效编码和传输机制

## 使用建议

### 新服务开发
1. 阅读错误码体系文档，了解模块分配和错误码定义规范
2. 阅读日志系统文档，配置适合的日志级别和输出目标
3. 在服务初始化时正确配置日志系统
4. 在关键路径添加适当的日志记录

### 现有服务迁移
1. 逐步替换现有的错误处理逻辑，使用统一的Status类
2. 将现有的日志输出迁移到新日志系统，保持兼容性
3. 添加trace_id支持，实现全链路追踪

### 运维监控
1. 根据生产环境需求调整日志级别和输出配置
2. 配置日志轮转策略，防止磁盘空间耗尽
3. 集成到现有的监控告警系统
